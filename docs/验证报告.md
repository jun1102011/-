# 实际轮荷分配与直行起漂验证（2026-09-22）

## 1. 当前结论

正式 `stabilizer_bar_repair.slx` 已写回实际轮荷分配，并增加可选 `drift_entry` 模式。正式目录模型已经从当前 GUI 普通初态连续运行30 s，完成“直行准备→入漂→接管→局部维持”。本轮没有启用路径LQR反馈和式4.10路径项，也没有验证退出漂移。

**起漂与维持通过当前仿真验收；转向理想角度精度没有全部通过早期门槛，悬架响应包含数据外推。**不能把本结果解释为原论文控制器已完整复现，也不能据此证明真实车辆或原轮胎/悬架数据覆盖了该工况。

最终复测数据：`results/simulink_formal25/raw.mat`、同目录原始CSV与 `LastRun*.evidence`。最终数值见 `results/delivery_metrics.json`。备份及写回哈希见 `source/hashes.json` 与 `results/deployment.json`。

## 2. 实际修改及其作用

### 实际轮荷与力分配

- 初始化入口删除 `p_f/p_r`；轮速执行块改收CarSim实际 `[Fz_FL,Fz_FR,Fz_RL,Fz_RR]`，同步周期0.01 s。
- 原轴力控制支路按同轴正轮荷比例分配纵向力。单轮失载权重为零；整轴有效轮荷不超过1 N时输出零分配力，原需求记入未实现残差。原始负轮荷及失载标志保留，不把负轮荷改成正常轮荷。
- 前后转移比例只记录。总左右轮荷差小于100 N时输出NaN及无效标志；未将约0.547写成新固定参数。
- 本轮局部反馈支路输出的是“前轮角、前/后目标滑移”，执行器继续使用四轮**实际Fx负载补偿**，不把旧轴力分配作为第二套并行执行输入。`repair_actual_load_allocation` 在起漂模式中是原轴力支路的对照诊断；它不等于起漂支路实际使用的纵向力命令。
- 轴力分配日志保留实际轮荷、权重、原轴力、分配轮力、实际轮力、失载和未实现需求；另记录不等左右纵向力产生的附加横摆力矩。数学边界用例及完整车体轮胎合力诊断均已保留。

### 过渡工作点与反馈

原五个状态种子不能直接组成输入连续的起漂过程。很小的负侧偏工作点已需要较大的后轴驱动滑移，同时前轴制动平衡纵向力。因此增加两点直行滑移建立，再衔接三点转弯和冻结终点，共七个调度点；另有GUI初速8.333 m/s的直行点。详见 `过渡工作点表.md`。

这次实际实现的次序为：**直线加速→后轴驱动滑移建立，同时前轴制动→横摆与负侧偏建立→局部接管**。这是为当前车辆建立的工程过渡，并非在参考侧偏曲线上简单增加一个固定反打脉冲。

求解过程还发现两类可复现的问题：

1. 沿用终点的悬架等辅助状态会污染其他工作点配平。本轮逐点释放后更新辅助状态；普通直行配平只固定速度、零横摆和前轴零滑移，侧偏由解给出，避免多施加一个约束。
2. 原七状态无结构局部辨识在普通直行点产生过大交叉反馈，虽然线性拟合模型预测稳定，实际释放却失败。普通点改用横向 `[β,r]←δ`、纵向 `[V,κf,κr]←[κf_d,κr_d]` 的结构约束后，实际维持通过。没有把线性闭环特征值当作实际稳定性证明；失败记录保留在 `point_hold_V12` 等目录。

终点反馈矩阵保持冻结；漂移/滑移建立点继续采用七状态反馈。普通点采用上述结构化反馈。使用实测输入响应、同一归一化原则设计局部反馈，未复制论文路径LQR的Q/R作为本轮全部控制参数。

### 执行器与状态机

- 轮速反馈增益沿用已验证局部设置12，轮速变化率预算40 rad/s²，力矩预算±3000 N·m；实际Fx负载、反馈、惯量三项分别保存。
- 前后滑移允许经过零点；本模式工程范围前轴−0.1～0.05、后轴−0.1～0.4，滑移变化率0.5/s。前轮输入变化率54.7945°/s，目标相对工作点偏差限制0.15 rad。这些是本控制库的工程设置，不是实车硬件能力证明。
- 控制更新0.01 s，转角执行0.0005 s。两种反馈只产生目标，共用一套执行器历史；接管不重置车辆或恢复配平快照。
- 普通准备：速度误差≤0.2 m/s、|β|≤1°、|AVz|≤0.02 rad/s连续1 s；10 s未满足记录准备失败，不开始入漂。
- 实验接管范围：`[0.5m/s,3°,0.08rad/s,0.02,0.04,2°,10°/s]`，对应 `[V,β,AVz,κf,κr,Roll,AVx]`。十四个单状态正负方向扰动释放均通过，未缩小阈值。**这不证明该七维方盒中所有组合扰动均能恢复。**
- 范围内连续0.3 s且接地正常、无持续力矩保护后，用0.5 s五次函数接管；离开范围时平滑退回过渡。回退已做合成状态机边界检查，本次实际起漂未触发回退，不能称实际回退鲁棒性已通过。

### 转向接口与数据范围

后右弹簧首次超过50 mm表端约1.027 s，后左约1.02775 s，发生在直行加速阶段、早于2.62 s入漂。告警记录后继续到30 s；没有扩表。日志亦有初始化限位块、外部动力链未使用发动机表的表端提示。成功运行的本轮日志未新增FY/MZ查表越界提示，不能由此断言全部组合滑移数据已经经过实车验证。

## 4. 如何复现与审查

从正式目录运行 `a001_new_Design_LQR_Controller.m`；设置 `repair_run_mode='drift_entry'` 与 `repair_entry_length=25` 后再初始化并仿真。入口本身只设置参数，不启动仿真。详见正式目录新增的“先看这里_实际轮荷与直行入漂.md”。默认 `normal` 保留原普通路径模式。

工作点库与当前Run_all.par哈希绑定。用户更改车辆后旧库失效会提示重新校核；此检查不禁止弹簧等表端外推，也不会因表端警告停止当前仿真。

核心算法在Simulink对应MATLAB Function块内；`repair_support/repair_entry_bank.json`仅保存固定工作点和增益。研究构建/求解/验证代码在本目录internal，不混入日常入口。原始数据、失败试验、配置证据保留在results，不以绘图平滑结果替代验收。

## 5. 下一步边界

当前证据支持“当前模型中普通初态可达该工作点，并能切入局部维持”。本次同时改变了过渡输入组织、普通点反馈结构和控制器力分配，不能把起漂改善全部归因于删除0.7/0.3。暂未做退出、路径层接回、组合扰动捕获、其他车速/半径及车辆参数变化的鲁棒性检验；后续应在这一成功基线之上单独改变一个因素。
